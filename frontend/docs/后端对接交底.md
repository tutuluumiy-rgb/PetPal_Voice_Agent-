# PetPal Voice Agent — 后端对接交底文档

> 给后端工程师的接入说明。本文档描述**当前前端已固定的契约**、**需要后端提供的能力**、以及**建议的传输与消息协议**，供接入真实后端（LLM / ASR / TTS / 历史等）时对齐。
>
> 版本：v0.1.0（前端骨架已可用，AI/语音/历史均为占位）
> 前端：Electron-Vite + Vue3 + TypeScript 桌面客户端；后端：由本仓库服务端接口团队提供。

---

## 1. 项目概览

**PetPal Voice Agent** 是一个桌面端 AI 语音虚拟形象客户端，由两个独立窗口组成：

- **宠物窗口**：220×240 透明、无边框、置顶的悬浮宠物（画布绘制球形形象），支持左键拖拽、右键弹出上下文对话面板。
- **控制面板**：800×620 的独立窗口，含语音参数、历史记录、人设配置、用户档案、宠物显示等多个设置页。

### 1.1 进程分层（前后端边界）

```
┌─ 渲染进程（renderer/）────────────────────────────────────────────┐
│  PetWindow.vue / ContextCard.vue / control-panel/*   纯 UI + 交互  │
└───────────────┬───────────────────────────────────────────────────┘
                │ contextBridge  →  window.api（仅白名单能力）
┌───────────────▼───────────────────────────────────────────────────┐
│  preload（preload/）   只做 IPC 桥接，无业务逻辑                      │
└───────────────┬───────────────────────────────────────────────────┘
                │ ipcMain（main/） 全部业务逻辑 + 全局状态
┌───────────────▼───────────────────────────────────────────────────┐
│  主进程（main/）  index.ts / ipc.ts / state.ts / windows.ts        │
│           │                                                       │
│           │ ★ 建议在此接入后端：主进程持有 WebSocket 长连接          │
┌───────────▼───────────────────────────────────────────────────────┐
│  后端服务（LLM / ASR / TTS / 历史 / 人设 / 语音参数）                │
└───────────────────────────────────────────────────────────────────┘
```

**关键安全约束：渲染进程不可直接访问网络**。`contextIsolation: true`、`nodeIntegration: false`，所有网络请求必须经主进程转发。因此**后端只对主进程开放连接**，接口无需暴露给浏览器端。

## 2. 前端已固定的契约（后端需遵守的部分）

前端 IPC 契约以 **`desktop/preload/types.ts`** 为单一事实源，主进程 / preload / 渲染进程三方共享。以下是当前已实现、后端接入时需对齐的内容。

### 2.1 枚举 / 数据模型

| 类型 | 取值 | 语义 |
|---|---|---|
| `PetMode` | `'chat' \| 'work'` | 全局工作模式：闲聊 / 工作 |
| `AuthPolicy` | `'full' \| 'ask'` | 权限策略：完全批准（工具/联网直接执行）/ 请求批准（需用户确认） |
| `DragPoint` | `{ screenX: number; screenY: number }` | 拖拽采样点（物理像素） |

### 2.2 IPC 通道清单（当前已注册）

> 通道名约定统一小写、冒号分隔。**建议后端事件按下表映射为 IPC 广播**（第 4 节给出完整映射）。

| 通道 | 方向 / 类型 | Payload → 返回 | 说明 |
|---|---|---|---|
| `mode:get` | R→M（invoke） | — → `PetMode` | 读取当前模式 |
| `mode-switch` | R→M（send） | `PetMode` | 通知主进程切换模式 |
| `mode:changed` | M→R（广播） | `PetMode` | 主进程侧模式变化推送给渲染端（如 ASR 语音指令切换） |
| `auth-policy:get` | R→M（invoke） | — → `AuthPolicy` | 读取权限策略 |
| `auth-policy:set` | R→M（send） | `AuthPolicy` | 更新权限策略 |
| `panel:open` | R→M（send） | — | 打开/聚焦独立控制面板窗口 |
| `pet:drag-start` | R→M（send） | `DragPoint` | 拖拽开始（主进程记录偏移） |
| `pet:drag-move` | R→M（send） | `DragPoint` | 拖拽移动（主进程节流 setPosition） |
| `pet:drag-end` | R→M（send） | — | 拖拽结束 |
| `panel:height` | R→M（invoke） | `{height, ballScreen?, ballInCanvas?}` → `{x,y}\|undefined` | 上下文面板开合时调整窗口尺寸（0=关闭）；返回实际窗口位置 |
| `pet:set-visible` | R→M（send） | `boolean` | 隐藏/显示球体 |
| `pet:get-visible` | R→M（invoke） | — → `boolean` | 读取可见性（控制面板"重新显示宠物"用） |
| `pet:visible-changed` | M→R（广播） | `boolean` | 可见性变化推送 |
| `app:version` | R→M（invoke） | — → `string` | 应用版本号 |
| `tts-start` | M→R（广播） | — | **预留**：TTS 音频开始播放 → 触发"说话"动画 |
| `tts-end` | M→R（广播） | — | **预留**：TTS 音频播放结束 → 切回待机 |

## 3. 建议的传输方案

**推荐：主进程 ↔ 后端使用 WebSocket 长连接**（与前端既有代码注释意图一致：`main/index.ts` 有"初始化 WebSocket 长连接、语音服务（ASR/TTS）、全局状态机"的 TODO）。

### 3.1 连接生命周期

1. **连接地址**：默认 `ws://localhost:PORT/ws`（本地桌面客户端直连）。端口号可在控制面板或配置文件指定（待定）。
2. **鉴权**：连接建立后客户端发送一次 `hello`/`auth` 握手消息（含 `clientId` / `token`），后端回 `hello_ok` 或拒绝。
3. **心跳**：客户端每 N 秒发 `ping`，后端回 `pong`（或协议内置 ping/pong）。
4. **断线重连**：主进程指数退避重连，重连后重新握手，并从服务端快照恢复状态（当前模式、历史游标等）。
5. **单连接承载命令与事件**：客户端→服务端为"请求"（request），服务端→客户端为"事件/响应"（event/response），用唯一 `id` 关联。

### 3.2 通用消息帧（任意一种，前后端二选一对齐）

**方案 A：JSON 消息（type 字段区分方向）**
```jsonc
// 客户端 → 服务端（请求/命令）
{ "type": "chat:send", "id": "c-123", "mode": "chat", "text": "你好球球" }
// 服务端 → 客户端（响应）
{ "type": "chat:send:ok",      "id": "c-123", "reply": { "text": "...", "action": "wave" }, "audio": "<tts-b64-or-url>" }
{ "type": "chat:send:error",   "id": "c-123", "code": "E_LLM_TIMEOUT", "message": "..." }
// 服务端 → 客户端（主动事件，无 id）
{ "type": "tts:start", "sessionId": "s-1" }
{ "type": "tts:end",   "sessionId": "s-1" }
```

**方案 B：SSE / 流式帧**（若后端用 HTTP + SSE，等价字段按 `type`/`id` 复用作帧分隔）。

> 流式回复建议：`chat:send:start → chat:send:delta(text chunk) → chat:send:done`；TTS 音频片段可随 delta 或单独 `tts:chunk` 事件下发。

## 4. 后端能力 → 前端映射（接口契约草案）

下表按功能域给出**建议接口**，前端将据此在主进程网关（`main/` 新增 service 层）兑现 `TODO`。字段名统一 **camelCase**，时间戳统一 **Unix 毫秒**。

### 4.1 对话 / LLM

| 动作 | 前端入口 | 请求 | 响应 | 备注 |
|---|---|---|---|---|
| 发送文本对话 | `chat:send` | `{ mode, text, sessionId? }` | 流式：`start → delta → done`；`done` 含 `{ reply, audio? }` | 回复可带 `action`（动作标签）与 `audio`（TTS 片段） |
| 中止生成 | `chat:abort` | `{ sessionId }` | `{ aborted: true }` | 驱动输入框"中止"按钮 |
| 生成状态 | `chat:running`（服务端事件） | — | `{ sessionId, running: true/false }` | 驱动 `isRunning`（右下角按钮变灰色中止） |

**动作标签约定**：LLM 输出中的 `【action:xxx】`（如 `【action:wave】`）由前端 `hooks.parseActionTag` 解析并映射为动画动作。后端只需保证"动作标签出现在回复文本中"即可，无需理解动画侧实现。

### 4.2 语音 ASR / TTS

| 动作 | 接口 | 说明 |
|---|---|---|
| 语音转文字 | `asr` | 客户端采集音频 → 后端返回文本（可复用 `chat:send` 链路，"文字输入 + 语音输入"统一入口） |
| TTS 开始 | `tts:start`（服务端事件） | 前端收到后触发"说话"动画 |
| TTS 结束 | `tts:end`（服务端事件） | 前端切回待机 |
| TTS 参数 | `voice:settings:get/set` | 见 4.5 |

### 4.3 历史记录

| 动作 | 接口 | 请求 | 响应 | 备注 |
|---|---|---|---|---|
| 列表 | `history:list` | `{ page, pageSize, mode? }` | `{ items: [{id, mode, time, preview}], total, page }` | 驱动 `HistoryView` 列表 |
| 搜索 | `history:search` | `{ keyword, page, pageSize }` | 同上 | 驱动搜索框 |

### 4.4 人设 / 用户档案

| 动作 | 接口 | 说明 |
|---|---|---|
| 人设读 | `personality:get` | 返回 markdown 文本（前端 `PersonalityView` 编辑 `personality.md`） |
| 人设写 | `personality:set` | `{ content }` 保存 |
| 用户档案读 | `user:get` | 返回 markdown 文本（前端 `UserProfileView` 编辑 `user.md`） |
| 用户档案写 | `user:set` | `{ content }` 保存 |

> 若由后端集中存这些 markdown 内容（非本地文件），后端提供读写接口即可；前端仅负责编辑区展示与保存按钮。

### 4.5 语音参数

| 字段 | 类型 | 范围 / 枚举 | 说明 |
|---|---|---|---|
| `volume` | number | 0–100 | 音量，滑块默认 80 |
| `pitch` | number | 0–100 | 音调，滑块默认 50 |
| `voice` | string | `default \| cute \| calm \| bright` | 音色，默认 `default` |

接口：`voice:settings:get` → `{ volume, pitch, voice }`；`voice:settings:set` → `{ volume, pitch, voice }`。

### 4.6 模式 / 权限

| 动作 | 接口 | 说明 |
|---|---|---|
| 模式设置 | `mode:set` | `{ mode: 'chat' \| 'work' }`；后端改动后回推 `mode:changed` 广播 → 前端单选态自动同步 |
| 权限策略 | `auth:policy:set` | `{ policy: 'full' \| 'ask' }`；`ask` 模式下工具/联网调用需返回待审批项，前端弹出审批 |
| 权限广播 | `mode:changed` / `auth:policy:changed` | 服务端主动事件，同步多个窗口 UI |

### 4.7 错误码约定

统一错误帧：
```jsonc
{ "type": "<op>:error", "id": "< 关联请求 id>", "code": "E_XXX", "message": "人类可读描述" }
```
建议错误码段：`E_UNAUTHORIZED`、`E_TIMEOUT`、`E_LLM_*`、`E_TTS_*`、`E_ASR_*`、`E_NOT_FOUND`、`E_VALIDATION`、`E_INTERNAL`。

## 5. 鉴权与安全约定

- **本地优先**：后端建议跑在 `localhost`，与桌面客户端同机；若需远程，客户端通过配置指定地址并携带鉴权 token。
- **单边可信**：主进程是渲染进程与后端之间的唯一通道；渲染进程不暴露任何网络能力（context isolation）。后端**不要信任**来自渲染进程的任何直接请求（本架构下不会出现，但作为纵深防御）。
- **明文最小化**：本地 IPC 明文即可；后端对外（若暴露公网）需 TLS + token 鉴权。
- **认证握手**：WebSocket 连接建立后先 `auth` 再业务，失败即关闭，服务端可限流防扫描。

## 6. 开发 / 联调约定

- **命名**：字段、事件、请求统一 camelCase；事件/接口名用 `域:动作`（如 `chat:send`、`history:list`）。
- **时间戳**：Unix 毫秒（`Date.now()`），历史记录 `time` 字段用此格式；前端展示格式化自理。
- **分页**：`page`（1 起始）+ `pageSize`；返回含 `total` 供前端"加载更多"。
- **流式**：采用方案 A 的 `start/delta/done` 三帧（或 SSE 事件同名），便于前端逐步渲染 + TTS 并行播放。
- **动作标签**：语法固定 `【动作名】`，形如 `【action:wave】`；后端在回复文案中直接携带，前端负责剥离与映射动画（后端无需关心动画实现）。
- **TTS 音频交付**：可后端 TTS 生成后以 base64 或临时 URL 下发，也可前端直接请求后端 TTS 端点；对齐后按方案 A 的 `audio` 字段而定。
- **联调顺序建议**：先 `auth` 握手 → `mode:get/chat:send` 文本链路 → `tts:start/end` 动画 → `history` → `personality/user` → `voice:settings` → `auth:policy`（审批）。

## 7. 验收清单（后端自测对照）

| # | 后端能力 | 对应用户侧效果 |
|---|---|---|
| 1 | `auth` 握手 + 心跳 + 断线重连 | 后端日志可见连接/重连，客户端不闪退 |
| 2 | `chat:send` 文本返回（流式） | 上下文面板消息区出现球球回复；输入框"运行中"→"可发送"切换正常 |
| 3 | `tts:start`/`tts:end` 事件 | 球球"说话"动画开始/结束（`hooks` 占位当前为空，事件能到达即可） |
| 4 | 回复含 `【action:xxx】` | 前端能解析（单元层面 `parseActionTag` 命中）；动画映射后续迭代 |
| 5 | `history:list/search` | 控制面板"历史记录"页出现真实数据、分页与搜索生效 |
| 6 | `personality:get/set`、`user:get/set` | 对应设置页能读、能保存 markdown 内容 |
| 7 | `voice:settings:get/set` | 音量/音调/音色滑块保存后回读一致 |
| 8 | `mode:set` + `mode:changed` 广播 | 模式卡片选中态主/被动切换均同步 |
| 9 | `auth:policy`（full/ask） | 权限卡片切换生效；`ask` 下工具调用触发待审批（后续迭代） |
| 10 | ASR 语音输入 | 语音 → 文本 → 对话链路（后续迭代接入麦克风） |
