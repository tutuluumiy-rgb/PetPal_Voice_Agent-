# 前端占位音频（Placeholder）契约 — 供前端实现 PlaceholderPlayer

> 前端交互层（UI）负责「何时播 / 播哪条 / 何时停」；本仓库（后端职责）提供
> **资源 wav + key 表 + 触发/停止时机映射**。前后端解耦：前端只按此契约播放，
> 不必理解后端 TTS 合成细节。
>
> 归属分工：
> - **本仓库**：生成 `renderer/public/placeholders/*.wav`（脚本 `backend/scripts/gen_placeholders.py`）。
> - **前端**：实现 `PlaceholderPlayer`（用 `Audio`/HTMLAudioElement 播放同源静态 wav、
>   独立通道与后端流式 PCM 播放器隔离），并按下方时机触发/停止。

---

## 1. 资源位置与 key 表

资源在 **`frontend/renderer/public/placeholders/<key>.wav`**（同源静态资源，构建后 `/placeholders/<key>.wav` 可访问）。
前端用 `new Audio('/placeholders/<key>.wav')` 播放。

| key | 文案（音频内容） | 主要场景 |
|-----|----------------|---------|
| `wake_here` | 我在呢～ | **唤醒响应**：KWS 命中后立刻播，随后进对话 |
| `wake_yes` | 嗯？我在～ | 唤醒的另一种语气（如再次确认唤醒） |
| `wait_processing` | 收到！我正在帮你查～ | 等待回复（第 1 条） |
| `wait_working` | 正在执行任务，请稍等～ | 等待回复（第 2 条） |
| `wait_almost` | 我还在处理，马上就好～ | 等待回复（第 3 条） |
| `tool_start` | 好的，这就帮你去办～ | 工具/任务早期反馈 |
| `task_failed` | 任务失败了，要不你再试试？ | 任务失败 |
| `task_retry` | 刚刚遇到点小问题，我们再试一次好不好？ | 任务失败/建议重试 |
| `conn_lost` | 连接好像断了，稍等让我重新连一下～ | 连接意外断开 |
| `conn_timeout` | 后台好像卡住了，我重新连一下～ | 后端超时/卡住 |

## 2. 建议的 PlaceholderPlayer 接口（前端实现）

```ts
interface PlaceholderPlayer {
  /** 播放指定 key；若已在播需能打断（切到新 key 或立即停止）。 */
  play(key: PlaceholderKey): void
  /** 立即停止当前占位并清相关计时器（回复已来/被打断等）。 */
  stop(): void
  /** 关停并释放（组件卸载/语音停止时调用）。 */
  destroy(): void
}
```
- **独立通道**：用一个 `HTMLAudioElement`（`new Audio()`）承载，**不要**与后端 TTS 流式 PCM
  播放器（`VoicePipeline` 的 AudioContext/播放时间线）混用、不共享状态。
- **可打断**：`play` 时若上一条未播完，先 `pause()`+`currentTime=0` 再播新的；`stop()` 同理。
- **等待循环**：`wait_processing → wait_working → wait_almost` 是前端自维护的计时循环
  （如 6s 未收到回复播 processing，之后每 9s 依次 working/almost，最多 3 条），
  收到「回复已来」即 `stop()` 并清计时器。

> 注意：渲染进程是 Electron 同源页面，`/placeholders/*.wav` 在 `pet.html`/`panel.html` 的
> CSP（`default-src 'self'`）下可正常 `Audio` 播放（同源 media 归 `default-src 'self'`）。

## 3. 触发时机（前端自判）

### 3.1 唤醒响应（本次重点）
- 前端在 **KWS 唤醒命中**时（`VoicePipeline` 的 `onWake` 回调，来源为主进程 `kws:wake` 广播）：
  1. 播 `wake_here`（「我在呢～」）；
  2. 随后进入对话（现有逻辑：`_enterConversation()` 连后端 8001 + VAD）；
  3. 收到后端首个回复事件（如 `reply_start`/`tts_start`/`reply`）时 `stop()`。
  > 也就是：`onWake` → `player.play('wake_here')` → 进对话；回复来了 → `player.stop()`。

### 3.2 等待回复
- `onSpeechEnd`（用户说完）后，若超时仍未收到 `reply`/`reply_start`/`tts_start` 等：
  按 §2 的 `wait_*` 循环播（`wait_processing` → `wait_working` → `wait_almost`）。

### 3.3 工具/任务
- 长任务 / 工具执行早期反馈：播 `tool_start`（本仓库 `_TOOL_PROGRESS` 只对快工具为空的场景，前端按需）。
- 任务失败：`task_failed`；建议重试：`task_retry`。

### 3.4 连接异常
- 语音 WS 意外 `onclose`：`conn_lost`。
- 后端超时/卡住：`conn_timeout`。

---

## 4. 停止时机（收到即 `stop()` 切占位）

前端收到后端以下**任一**事件时，立即停止占位并清计时器：

`reply_start` / `reply` / `reply_append` / `tts_start` / `tts_end` / `reply_end` /
`barge_confirm` / `barge_reject` / `stop_playback` / `resume_playback` / `stop_placeholder` / `asr_final`

- `stop_placeholder`：后端显式要求停占位（本仓库可发，前端收即切）。
- 其余：回复/播放/打断已接管，占位应让位。
