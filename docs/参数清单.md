# PetPal Voice Agent 参数清单（前端 / 后端 / 评测中心）

> 依据当前代码逐文件整理：每个参数给出「设置 / 含义 / 说明」。
> 本清单只描述参数，不涉及任何代码改写。
> 生效原则：后端改动 → 重启 `python main.py`；前端改动 → 重新构建 Electron；
> 纯文件类（提示词 / 用户档案 / 词表 / wav）免编译，重启后端即生效。

---

# 一、后端 `backend/`（FastAPI，默认端口 8001）

## A. 环境变量 —— `backend/.env`（服务选型与密钥）

| 参数 | 设置 | 含义 | 说明 |
|---|---|---|---|
| `LLM_PROVIDER` | `deepseek` \| `qwen` | 大模型供应商切换（闲聊模式） | 决定 chat 模式走 DeepSeek 还是 Qwen 分支；改 .env 重启生效 |
| `WORK_MODE_LLM_PROVIDER` | 默认 `deepseek` | 工作模式 LLM 供应商（新增） | 工作模式固定走 DeepSeek（工具调用更稳）；可改 `qwen` 覆盖。**Worker 后台任务同用该配置** |
| `DEEPSEEK_API_KEY` | 密钥 | DeepSeek 鉴权 | 不填则 LLM 启动报错 |
| `DEEPSEEK_MODEL` | 默认 `deepseek-v4-flash` | DeepSeek 模型名 | **工作模式默认**（用户确认 v4 flash）；`.env` 可覆盖为其他模型；改模型不影响管道代码 |
| `DEEPSEEK_BASE_URL` | 默认 `https://api.deepseek.com` | DeepSeek 接口地址 | 私有化部署时改这里 |
| `QWEN_LLM_MODEL` | 默认 `qwen-flash` | Qwen 模型名 | `LLM_PROVIDER=qwen` 时生效；可选 qwen-plus/qwen-max |
| `QWEN_LLM_BASE_URL` | 默认 `https://dashscope.aliyuncs.com/compatible-mode/v1` | Qwen OpenAI 兼容地址 | 私有化时改 |
| `QWEN_LLM_API_KEY` | 密钥 | Qwen 鉴权 | 留空则回退用 `DASHSCOPE_API_KEY` |
| `ASR_PROVIDER` | `ali` 等 | 识别服务选型 | 换实现需在 `providers/` 加类并注册 |
| `ASR_MODEL` | 默认 `qwen3-asr-flash-realtime` | 流式识别模型 | 仅支持 `*-realtime` 流式模型 |
| `ASR_API_KEY` | 密钥 | ASR 独立鉴权 | 留空则用 `DASHSCOPE_API_KEY` |
| `ASR_BASE_URL` | 默认 `wss://dashscope.aliyuncs.com/api-ws/v1/realtime` | ASR WebSocket 地址 | 私有化时改 |
| `TTS_PROVIDER` | `ali` \| `minimax` | 合成服务选型 | MiniMax 时走 `providers/minimax_tts.py` |
| `TTS_MODEL` | 默认 `qwen3-tts-instruct-flash-realtime` | 合成模型 | instruct 版支持自然语言语气指令；`*-realtime` 为流式 |
| `TTS_VOICE` | 默认 `Mochi` | Qwen 音色 | 如 `Mochi`=沙小弥；前端"语音设置"可另行覆盖 |
| `DASHSCOPE_API_KEY` | 密钥 | 阿里云百炼通用密钥 | ASR/TTS 共用 |
| `MAX_AGENT_LOOPS` | 默认 `6` | 工具循环最大轮数 | 防死循环；简单问题一般 1 轮即答 |
| `LLM_TIMEOUT_S` | 默认 `45` | 单次 LLM 调用超时 | 与后端 `SPEAKING_PLAYBACK_TIMEOUT_S=45` 对齐 |
| `ACTIVE_USER` | 默认 `user_001` | 当前启用用户 | 决定注入哪个用户档案与记忆目录 |
| `SEARCH_PROVIDER` | `mock` \| `tavily` \| `bing` | 联网搜索实现 | mock 不需要 key 即可跑通链路 |
| `SEARCH_API_KEY` | 密钥 | 搜索服务鉴权 | tavily/bing 需要 |
| `SEARCH_BING_ENDPOINT` | 地址 | Bing 搜索端点 | `SEARCH_PROVIDER=bing` 时使用 |
| `MINIMAX_API_KEY` | 密钥 | MiniMax 鉴权 | `TTS_PROVIDER=minimax` 时必需 |
| `MINIMAX_MODEL` | 默认 `speech-2.8-turbo` | MiniMax 模型 | 官方 T2A v2 系 |
| `MINIMAX_VOICE_ID` | 默认 `socialmedia_female_2_v1` | MiniMax 音色 | 可用 `known_voice_ids()` 列表 |
| `MINIMAX_BASE_URL` | 默认 `https://api.minimaxi.com` | MiniMax 端点 | 海外用 `https://api.minimax.io` |
| `MINIMAX_GROUP_ID` | 旧版账户 | 分组 ID | 新版项目密钥可不填 |
| `MINIMAX_TRANSPORT` | `http`（默认）\| `ws` | 连接方式 | http 首包 0.2~0.3s；ws 长连接多句复用，唤醒预热后可降到 ~2.7s |
| `MINIMAX_SAMPLE_RATE` | 默认 `24000` | MiniMax 输出采样率 | 前端按 24k 播放 |
| `MINIMAX_FORMAT` | 默认 `pcm` | 音频格式 | |
| `MINIMAX_TEXT_NORMALIZATION` | 默认 `false` | 服务端文本归一化 | `true` 时开 |
| `PORT`（或 `python main.py 8002`） | 默认 `8001` | 后端监听端口 | 前端硬编码 8001，改端口需同步改前端 |

## B. 模型配置组 —— `backend/model_config.py`（控制面板「模型配置」页可在线改，写回 .env）

| 参数 | 设置 | 含义 | 说明 |
|---|---|---|---|
| LLM 组 `url / api_key / model` | 见 .env | 大语言模型 | 面板保存后写回 `DEEPSEEK_MODEL/API_KEY/BASE_URL` 或 `QWEN_LLM_*` |
| ASR 组 `url / api_key / model` | 见 .env | 流式识别 | 写回 `ASR_BASE_URL/API_KEY/MODEL` |
| TTS 组 `url / api_key / model / voice` | 见 .env | 流式合成 | 写回 `TTS_BASE_URL/DASHSCOPE_API_KEY/TTS_MODEL/TTS_VOICE` |
| 识图组 vision | 默认 `glm-4.6v-flash` | 普通图片消息识别 | 写回 `VISION_*` |
| 视频组 video | 默认空 | 视频模型 | 写回 `VIDEO_*`，Base URL 需以 `/v1` 结尾 |
| `AVAILABLE_MODELS` | 静态目录 | 「获取可用模型」返回的候选 | 新增候选直接改这个字典 |

## C. 后端运行时与双层打断 —— `backend/main.py`「🎛 参数区」

| 参数 | 设置 | 含义 | 说明 |
|---|---|---|---|
| `HOST`（env） | `127.0.0.1` | 后端监听地址（安全审计 F1） | 默认只绑本机回环；要局域网显式设 `HOST=0.0.0.0`（随之而来的 Origin 白名单仍按本机/localhost 放行） |
| `MGMT_TOKEN`（env） | `fake-token` | /ws/mgmt 管理鉴权 token（安全审计 F1） | 生产建议改随机长 token 并在前端 `backendGateway.ts` 同步；不设置时默认 `fake-token`（仅本地） |
| `ALLOW_BASH`（env） | `0` | bash 工具开关（安全审计 F3） | 语音链路默认禁用 bash（防 RCE 面）；工作模式确需时设 `ALLOW_BASH=1` 重启后端 |
| `WORKSPACE_ALLOWLIST`（env） | 空（默认） | **额外工作区白名单（新增）** | `;` 分隔多个绝对目录（如 `G:\petpal测试`）；`read/write/edit`（及 Worker）在这些目录内的路径解析同样放行，项目工作区之外、白名单之外的路径仍拒绝 |
| `POST_SPEECH_GUARD_FRAMES` | `10`（1帧≈30ms） | 说话后静默保护期 | 调大更防回声；调小接话响应更快 |
| `BACKEND_VAD_THRESHOLD` | `0.6` | 后端 Silero 人声概率阈值 | **与前端起提对齐（用户确认：前端 0.6/0.4 滞回）**——占比=前端口径下的人声帧占比。近窗静音场景由 `CONFIRM_TRUST_FRONTEND_SILENT_RMS` 分支接管（不依赖此阈值） |
| `CONFIRM_SPEECH_RATIO` | `0.03` | 长缓存人声帧占比阈值 | ✅已改造：长/短分档点改按 `CONFIRM_ENERGY_CACHE_MS`；素材=缓存（preRoll 退出物理判据）。0.05→0.03：轻声插话占比可低至 0.0x |
| `CONFIRM_SPEECH_RATIO_SHORT` | `0.3` | 短缓存（更严）人声占比 | 缓存 <1200ms（能量闸不可用）时是唯一物理判据，防人声类误报 |
| `CONFIRM_MIN_AUDIO_MS` | `200` | 复核材料最短总长 | 材料总长（含 preRoll）不足 200ms 时宁可不打断 |
| `CONFIRM_WINDOW_MS` | `320` | 二次确认取音频窗口 | 近窗=**合并素材（preRoll+缓存）尾部** 320ms（聚焦开口段；缓存短时 preRoll 首字纳入判定输入）；基线=缓存头部 320ms（球球开播段）。**768→320 回落（用户确认）**：宽窗会把回声/环境噪声帧框进来稀释人声占比；消息滞后由 `CONFIRM_RETRY_MS` 兜底 |
| `CONFIRM_ENERGY_JUMP` | `3.0` | 能量跃升比值阈值 | 近窗 RMS / 头部基线 RMS；低于则判平稳噪音/回声拒绝打断。调大更严、只认明显突变。⚠️ 勿轻易调小：球球自身字间能量波动 jump 常见 1.3~2，调小会把西西自身波动误判成插话 |
| `CONFIRM_RETRY_MS` | `120` | **静音窗重试（新增）** | 首验未通过且近窗静音（speech_start 先于音频帧到达）→ 延迟 120ms 用新缓存重验一次；仍失败才定论。0=关闭 |
| `CONFIRM_TRUST_FRONTEND_BASELINE_RMS` | `30` | **基线静音→信任前端（新增）** | 首验+重验都失败且【缓存头部（球球回声区）RMS】<此值（麦克风采不到球球回声=无回声误触风险）→ 物理复核材料不可信 → 信任前端 VAD（同款 Silero 0.6起提×6帧判人声）确认打断。**判断用头部基线而非近窗**：近窗可能有微弱开口能量（RMS 几十~百）但在 0.6 口径下占比仍 0，属正常边界。误断有挂起+语义裁决兜底。0=关闭（严格物理复核） |
| `CONFIRM_RECENT_MIN_RMS` | `50` | **基线静音时近窗能量下限（新增）** | 基线 RMS≤30（mic 听不到球球=分离度好）时占比闸会系统性误拒轻声插话（实测 RMS137/峰值1891 但占比 0.00）→ 近窗 RMS≥此值直接确认打断；低于则仍走占比闸兜底。0=关闭此分支 |
| `CONFIRM_ENERGY_CACHE_MS` | `1200` | **能量闸启用/占比分档门槛（改造#2 新增）** | 以 `speaking_audio_cache` 长度判定（不含 preRoll）：≥1200ms 走能量闸+占比 0.03；<1200ms 跳过能量闸、占比用 0.3。隐含假设：打断发生在球球开播 ≥(1200−192)=1008ms 后（前端判定窗口已改 192ms），保证头部 512ms 是纯球球回声 |
| `SUPPLEMENT_WINDOW_MS` | `1200` | **补充说明窗口（端点检测·改造#7）** | 端点判定"可能未完"（p≤0.5）时才开此窗口等续说：窗口内用户继续说话（≥192ms 前端档）→ 同一 turn 补充（turn_id 复用、revision+1、音频并入同一 ASR 会话、旧 LLM/TTS 失效）；窗口结束无续说 → 正式提交。**非打断专有**：所有链路（正常收话/打断后收话）统一经过 |
| `SMART_TURN_MODEL_PATH` | `backend/models/smart_turn_v3.onnx` | SmartTurn 话轮完结判定模型 | **已放置** v3.2-cpu（int8 量化 8.7MB，含 80 层 log-mel 的 Whisper Tiny 编码器）。缺失/加载失败 → judge 返回 None → 走 `SMART_TURN_FALLBACK` |
| `SMART_TURN_THRESHOLD` | `0.5` | "话是否完整"概率阈值 | p > 阈值 → 话完整 → 直接提交；p ≤ 阈值 → 可能未完 → 开补充窗口。默认 0.5（实测标定，`scripts/smart_turn_calib.py` 31 样本：θ=0.5→81% 一致；θ=0.3→74% 更差）。**职责边界**：SmartTurn 只判"话是否完整"，"是否说完话"由前端 VAD 静音时长判定（`redemptionFrames`） |
| `SMART_TURN_FALLBACK` | `direct` | 无法判定时（无模型/无音频/推理失败）的端点策略 | `direct`=视为已说完直接提交（等价旧行为）；`window`=视为未完统一开窗 |
| （前端）`SMART_TURN_MAX_MS` | `8000` | `speech_end` 携带的"该说话段"**整段话**上限 | 与上游 pipecat `max_duration_secs=8` 对齐：前端在 speech 窗口内累计整段话（含预卷与尾静音，超 8s 保尾截断）随 `speech_end` 的 `audioB64` 上报。**窗口口径**：实测标注数据（`scripts/smart_turn_probe.py`）整段话判别 90% vs 旧"最近 1600ms"切片 80%，且尾部切片会把"未完"误判成"说完"（韵律上下文被截断） |
| （后端）`SMART_TURN_REJUDGE_MS` | `600` | **尾静音重判（模型驱动提前提交）** | 首判 p≤阈值开窗后，窗口期继续收集**真实尾静音**（前端持续推帧 → `handle_audio_frame` 收进 `smart_turn_tail`），到点用 [整段话+真实尾静音] 再判一次：p>阈值 → **提前提交**（多数场景 ~600ms 提交而非等满 1200ms）；仍 p≤阈值 → 维持窗口按超时提交。0=关闭。实测依据：突兀收尾的完整句首判 0.26，补 300ms 真实静音 → 0.88 |
| （调试）`SMART_TURN_LOG_AUDIO` | `0` | 判定音频段 dump（env `SMART_TURN_LOG_AUDIO=1`） | 每次端点判定（含重判扩展段）写 16k mono wav 到 `smart_turn_audio_log/`，供真实语音标定阈值/诊断误判 |
| `SPEECH_TIMEOUT_S` | `30` | listening 收音超时兜底 | 无 speech_end 自动退出收音；仍在收音频则续期（最多 2 次） |
| `SPEAKING_PLAYBACK_TIMEOUT_S` | `45` | speaking 播放卡死兜底 | 逐句完成会滑动重 arm，长回复不会被误掐 |
| `SILERO_MODEL_PATH` | `testboard/vad/silero_vad.onnx` | 后端 VAD 模型路径 | 换模型改路径 |
| `MAX_SPEAKING_CACHE` | 2 秒 PCM | 说话期间音频缓存上限 | 打断时回放给 ASR |
| `cache_tail_ms` | `200` | 打断喂 ASR 的缓存尾部长度 | 1000ms 会引入球球回声污染；200ms 平衡首字补全与污染 |
| speech_start 过期判定 | `8s` | 重复触发时的重置依据 | 上次 speech_start 超 8s 无结束则重置 |
| `FILLER_WORDS` | `嗯|啊|哦|额|呃|噢|哎|唉|嗯嗯|啊啊|哦哦|额额|呵呵|嘿嘿` | 语气词黑名单 | ASR 结果仅含这些词直接丢弃；自定义用 `\|` 分隔 |
| `_TOOL_PROGRESS` | 各工具文案 | 工具开始时的罐头进度播报 | 空串=不播（calculator/ask_user_questions）；可改文案 |
| `_memory_summarizer` | `temperature=0.3, max_tokens=1200` | 记忆抽取的独立小调用 | 不污染主回复链路 |

## E. LLM 生成与句子切分 —— `backend/providers/llm.py`

| 参数 | 设置 | 含义 | 说明 |
|---|---|---|---|
| `temperature` | chat `0.7` / work `0.5`（`CHAT_MODE_TEMPERATURE`/`WORK_MODE_TEMPERATURE` 可覆盖） | 生成随机性 | **按模式区分默认值**：温度越高答复越发散——闲聊 0.7、工作模式 0.5（任务执行/工具调用稳定优先）；评测中心 Step4 可临时注入覆盖 |
| `max_tokens` | `15000` | 单次生成上限 | 流式调用两处共用 |
| `SENTENCE_ENDS` | `。！？!?；;…、\n` | 句子切分标点 | 遇到即切句，语速节奏由此决定 |
| `FIRST_SENTENCE_MAX_CHARS` | `12` | 首句字符上限 | 达到即强制切短句 → 首句更快开口 |

> 另：评测库中 `tool_call_success` 判定=后端按「开始调用：{工具名}」事件精确比对 `expected_tool`；模型直接回答（未调工具）记 `none`（不算 False），只有调了但调错才记 `false`。

# 附：调参优先级建议（常见优化场景）

- **首句响应慢** → 前端 `positiveThreshold`/`minSpeechFrames`（更快判定开口）、后端 `POST_SPEECH_GUARD_FRAMES`、LLM 切句 `FIRST_SENTENCE_MAX_CHARS=12`、`TTS_PROVIDER=minimax` + `MINIMAX_TRANSPORT=http`（或 ws + 唤醒预热）

- **工具调用不爱调/乱调** → `prompts/agent.md` + `chat_system_prompt.md` 工具准则（**已强化**：删除"简单问题不用调"，改为"需要实时/外部信息时必须调工具、禁止编造数据"，2025-02）；模式白名单（`tools/loader.py`）；工具 schema 合规（原生 function calling：`build_tools_list` 输出 name/description/parameters，复合参数如 `edit.edits` 需自带 description，可跑临时校验脚本检查）；评测集 `expected_tool` 口径对照
