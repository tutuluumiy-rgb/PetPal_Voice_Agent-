# 记忆模块改造计划（v2，按用户方案整体替换）

> 本文档固化「记忆模块」整体改造的设计：**文件系统层 + 上下文整理 + 压缩 + 三分工 + chat 触发**，
> 作为实现对照。相较于 v1（L0~L3 多 jsonl 分层），本版**扁平化、markdown 文件优先、渐进式上下文**。

---

## 0. 总体决策（已确认）
- **整体替换**为下面的文件系统方案；v1 的 `memory_store.py`（events.jsonl/facts.jsonl/self.md）逐步退役/迁移。
- **压缩异步执行，不阻塞**（因 compact_ratio=0.7、余量富足）。
- **chat 模式加轮数触发压缩**：完整对话轮数超过 **15 轮**即触发，保留最近 15 轮原文。

---

## 1. 文件系统层（working_dir = backend/）
```
backend/
├─ working_dir/            （下方各项均在此）
│  ├─ MEMORY.md                 # 长期记忆主干（≤1000 字；后续改造为向量化，暂不管）
│  ├─ memory/
│  │  └─ YYYY-MM-DD.md          # 每日日志（L1 事件级，按日；语义/事实记忆）
│  ├─ tool_result/
│  │  └─ <uuid>.txt             # 工具调用完整结果（设 3 天过期，自动清理）
│  └─ dialog/
│     └─ YYYY-MM-DD.json        # 每日对话存档（结构化）
```
- `MEMORY.md`：长期记忆主干，跨会话事务/知识。≤1000 字（用 **token 数判断**控制，非导航摘要）。
- `memory/YYYY-MM-DD.md`：每日日志，**语义/事实记忆（=L1 事件/情景）**。
- `tool_result/<uuid>.txt`：工具结果完整内容，**3 天过期自动清理**。
- `dialog/YYYY-MM-DD.json`：按日对话存档（结构化摘要）。

## 2. 推理前上下文整理

### 2.1 工具结果压缩
- 完整内容保存到 `tool_result/<uuid>.txt`。
- 上下文**只保留截断片段 + 续读提示**（提示可用续读/读取 `tool_result/<uuid>.txt`）。
- **近 N 条工具结果不截断**（取 10，chat 与 work 一致）。

### 2.2 check_context（拆分判定）
**占用预算公式**：
```
history_budget = max_input_length * compact_ratio * 0.95
               - system_prompt_tokens - summary_tokens
```
- `max_input_length` = 模型输入上限（qwen-flash = 1M token）
- `compact_ratio` = 0.7
- `system_prompt_tokens` / `summary_tokens` = **按估算**（本地 `_estimate_tokens`）

**当已占用历史 token > history_budget 时触发上下文拆分**，拆为两组：
- `messages_to_compact`：较早的历史消息（进入压缩）
- `messages_to_keep`：最近完整保留（**work 5 轮 / chat 15 轮**，加 **15000 token 双重限制**）
- 拆分保证：不破坏 user-assistant 对话对、不拆 tool_use/tool_result 配对（复用现有 `group_into_turns`）。

### 2.3 system_prompt_tokens 构成
```
user_profile          # 按用户 id 选文档输入；结构化事实（=L3 自传，融合 L2）
agent.md              # 现 system_prompt.md 改名
work_system_prompt.md / chat_system_prompt.md   # 需补充 chat_system_prompt.md 并适配 chat 链路
voice_style.md        # 语气输出
personality.md        # 宠物人格
MEMORY.md             # 长期记忆主干
YYYY-MM-DD.json       # 只输入【昨天】的；用户主动问询可查找
```

### 2.4 对话压缩（compact_memory）
- **同步调用语义 → 实际异步执行，不阻塞**（0.7 余量富足）。
- **仅在第 2.2 步超过阈值时执行**；压缩比例按 **0.1** 设计。
- 结构化压缩，五层字段：
  ```
  goal          用户目标
  constraints   约束和偏好
  progress      任务进展
  keydecision   关键决策
  nextsteps     下一步计划
  ```

### 2.5 记忆持久化（异步，不阻塞主流程）
> 触发 = **压缩后 + 每日主动触发一次**（不再是"会话结束"触发）。
- **重要信息写入 `MEMORY.md`**：长期记忆主干层。（后续改造为向量化存储，暂不管）
- **`memory/YYYY-MM-DD.md` / `dialog/YYYY-MM-DD.json`**：每次触发压缩时**异步新增或更新**，按日期命名、结构化摘要（=L1 语义/事实）。

## 3. 三分工（已确认，杜绝重复/矛盾）

| 层 | 对应旧概念 | 存什么 | 写谁 | 注入策略 |
|---|---|---|---|---|
| **user_profile（=L3 自传，融合 L2）** | 用户身份/偏好/关系画像 | 用户是谁、喜欢什么、习惯、长期目标、与球的关系 | `memory_add` 主动 + 每日日志沉淀 + 对话中更新 | **恒注入**（`<user-profile>` 人设/偏好基线） |
| **MEMORY.md（长期记忆主干）** | 跨会话事务/知识主干 | 用户托付的长期工作内容、约定、里程碑、结论（偏事务/项目）。≤1000 字 | 压缩后异步 + 重要信息主动写入 | **恒注入**（≤1000 字，预算截断） |
| **YYYY-MM-DD.json（=L1 事件/情景）** | 按天事件事实档案 | 某天聊了什么/做了什么（原始/低层事实），是上面两层的**沉淀原料**，也供"某天发生过什么"回溯 | 压缩后 + 每日主动一次（异步） | **只注入昨天**；更久按需查询 |

**一句话分工**：
- `user_profile` = 记住"你是怎样的人"（身份/偏好，稳定画像）
- `MEMORY.md` = 记住"我们长期的事务/知识"（任务、约定、里程碑）
- `YYYY-MM-DD.json` = 记住"最近发生过什么"（按天原始事件，作为上面两层原料，也供回溯）

**映射**：L1(事件) → 每日 json；L2(事实)+L3(自传) → user_profile；MEMORY.md → 独立事务/知识主干。

## 4. 触发方式
- `user_profile`、`agent.md`、`personality.md`、`MEMORY.md`、`YYYY-MM-DD.json` **均支持主动触发**（写一个写入工具说明，或在现有 `memory_add/memory_forget` 基础上改）。
- `user_profile`、`personality.md` 支持**前端修改/查看**，预留接口。

---

## 5. chat 模式轮数触发压缩（问题结论）
- **需要**：chat 闲聊句子短、token 几乎不会到 0.7 阈值 → 纯 token 触发下 chat 上下文会无限累积（成本/变慢/稀释人设）。
- **方案**：双条件触发（先到先触发）：
  1. **token**：已占用历史 > `history_budget`（见 2.2）。
  2. **轮数**：完整对话轮数 > **chat_max_rounds = 15**。
- 压缩时**保留最近 15 轮原文**，更早的压成五层摘要；**异步执行，不阻塞**。

---

## 6. 实施顺序（分阶段，避免一次大爆炸）
1. **文件系统层**：`MEMORY.md` + `memory/` + `dialog/` 读写 + `tool_result/` 落盘/3 天过期。
2. **上下文整理**：`check_context` 预算公式 + work5/chat15 + 工具结果片段+续读（复用 `group_into_turns`）。
3. **压缩**：五层字段/比例 0.1 + 压缩后异步写每日 json + MEMORY.md。
4. **补 `chat_system_prompt.md` + 适配 chat 链路**；`system_prompt.md` → `agent.md` 改名。
5. **前端接口**：user_profile / personality 查看修改。
6. **退役/迁移** v1 memory_store。
