## 二、本阶段决策（已与用户确认）

1. **Mock 协议**：按 `frontend/docs/后端对接交底.md` 方案 A（WebSocket + `{type,id,...}` JSON 帧）。
   Mock 端口 **9000**：`ws://127.0.0.1:9000/ws`。

   控制/设置走主进程。
3. **职责分工**：后端（本仓库）负责 LLM/ASR/TTS/工具/状态机/历史/KWS/语音管线样板；
   前端 Agent 只改 UI/交互。
4. **先测试再修改**：本环境沙箱无法构建/运行 Electron，由用户在本机 `npm install && npm run dev` 验证。

## 七、KWS 唤醒词（本轮，代码已落地 · 待本机验证）

### 决策（已与用户确认 + 技术校正）
- **唤醒词**：自定义「你好小伴/宠伴/球球」不在 sherpa-onnx 预训练 KWS 词表 → **改用模型现成词**，
  默认示例 **「你好小米」**（`download_kws.py` 打印模型真实词表，可换任意现成中文词）。
- **实现层（最终定）**：**Electron 主进程 + `sherpa-onnx-node`**（官方 Node 绑定，npm 确定存在）。
  - 弃渲染进程 wasm：官方 wasm 版缺轻量独立运行时、`sherpa-onnx-wasm` 非 npm 包。
  - 麦克风在渲染进程采集（getUserMedia）→ 帧经 IPC `kws:feed` 喂主进程推理 → 命中 `kws:wake` 广播回渲染进程进对话。
- **交互**：待机听唤醒 → 命中进对话 → `reply_end` 回待机（用户选定）。

### 依赖 & 验证（需用户本机，沙箱无法联网/无法跑 Electron）
1. `cd frontend && python scripts/download_kws.py`（官方 `kws-models` URL，解压模型到 `frontend/resources/kws/`，打印关键词表挑词）。
