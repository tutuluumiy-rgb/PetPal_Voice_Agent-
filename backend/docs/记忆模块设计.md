# 记忆模块设计（Memory）· 分层实现

> 记录记忆模块的分层机制、触发时机、主动工具、接口契约与接入点。
> 分工：**后端（本仓库）** 负责抽取/存储/注入与接口定义；**前端** 按契约做"记忆管理页"UI。

---

## 0. 核心区分
- **人格（Self/Identity）＝ 球是谁**：`backend/prompts/personality.md`（静态人格），本模块**不动**。
- **记忆（Memory）＝ 球记得什么**：本模块，动态积累，记录用户与共同历史。

---

## 1. 记忆分层（L0 ~ L3）

| 层 | 名称 | 时间尺度 | 内容 | 谁写 / 何时 |
|---|---|---|---|---|
| **L0** | 工作记忆 | 一次对话内 | 当前轮 + compaction 检查点 | **已有**（session_store + context_builder），不新建 |
| **L1** | 事件/情景记忆 | 一次会话 | 该会话"值得记"的事件/任务要点 | LLM，**会话结束**时抽一次（非 per-run） |
| **L2** | 语义/事实记忆 | 跨会话长期 | 用户稳定事实：身份/偏好/习惯/家庭 | LLM，周期从 L1 沉淀（去重/合并） |
| **L3** | 自传/关系记忆 | 极长最稳定 | 用户整体画像 + 里程碑 + 长期目标 + 关系状态（浓缩叙事） | LLM，周期从 L1+L2 重写 |

**注入权重**：L3 > L2 > L1（预算有限时谁优先）。

---

## 2. 触发机制（关键设计）
- **L1 不在每次 run 抽取**（run = 一次输入处理，太频）。改为**一次会话结束**统一抽：
  - **会话结束判定**：WebSocket 断开（`/ws/audio` 连接关闭）即视为一次会话结束，
    在 `cleanup_session` 里 `asyncio.create_task(_archive_session_memory(session))` 后台归档。
  - 归档内容：`session.store.transcript()` → `(role, text)` pairs → `memory_extractor.on_session_end(...)`。
  - 补充（可后续加）：空闲超时窗口（`session_idle_timeout_s`）与内容量兜底
    （`session_archive_text_threshold`）作为补充判定，当前以"断开即归档"为主。
- **L1→L2 沉淀**：`on_session_end` 计数，每 `l2_consolidate_every_n_sessions` 次会话触发一次
  `consolidate`（L1 逐条判 new/merge/drop，沉淀后清空 L1）。
- **L2→L3 重写**：每 `l3_rebuild_every_n_consolidations` 次沉淀触发一次 `rebuild_l3`（覆盖式重写）。

---

## 3. 主动记忆（工具）
用户主动说"记住 XX / 忘掉 XX"时，由 LLM 调用工具（与现有 function calling 同机制）：
- **`memory_add(text, category)`**：写入记忆。category ∈ `identity|preference|fact|event|goal`。
  **层由类别规则映射**（避免 LLM 乱填层）：
  `identity/preference/fact → L2`；`event → L1`；`goal → L3 语义（存 L2 并标记）`。
- **`memory_forget(text)`**：按 id 或内容关键词删除（L1/L2）。
- 白名单：`tools/loader.py` 中 `memory_add/memory_forget` 已注册；work 全开，chat 按
  `MEMORY_TOOL_CHAT_ENABLED`（默认 True）开放。approval 声明 `REQUIRE_APPROVAL`
  （语音场景 `enforce_approval=False` 默认自动放行）。
- `tools/memory.py` 通过 `bind_memory(store, extractor)` 注入全局引用（main.py 初始化时绑定）。

---

## 4. 注入
`context_builder.build_model_context(...)` 新增参数 `memory_blocks`（来自 `memory_store.recall_blocks()`）：
- 注入一段 `system`：`## Long-term Memory (about the user)\n...`，按 L3 > L2 > L1。
- **预算 clamp**：`memory_max_tokens`（默认 1800/turn），超了按权重截断（L3 必全，L2 按 confirmed/ref_count，L1 可选）。
- **未确认事实**（`confirmed=False`）默认不注入。
- 接入点：`agent_runtime.run_agent_loop` 传 `memory_blocks=memory_store.recall_blocks() if memory_store else None`。

---

## 5. 存储（`backend/memories/`，已 gitignore）
- `events.jsonl`（L1）/ `facts.jsonl`（L2）/ `self.md`（L3，可重建）。
- 进程常驻 `MemoryStore` 单例（线程安全：内存列表 + 短锁 + JSONL append/重写）。
- L3 是派生产物（源删可重建）；整体可 `clear`。

**锁注意**：`threading.Lock` 不可重入。`recall_blocks()` 等绝不能在持锁时再调
`l3_narrative()/l2.all()/l1.all()`（它们各自拿同一把锁）——必须单层锁内直接读内部结构。
（已踩坑并修复：曾因 `recall_blocks` 嵌套拿锁导致 run 全链路死锁。）

## 6. 配置（`backend/agent_config.py`）
`MEMORY_ENABLED`、`SESSION_IDLE_TIMEOUT_S`(45)、`SESSION_ARCHIVE_TEXT_THRESHOLD`(4000)、
`MEMORY_MAX_TOKENS`(1800)、`MEMORY_L1_MAX_ENTRIES/L2_MAX_ENTRIES`(200)、
`MEMORY_L2_CONSOLIDATE_EVERY_N_SESSIONS`(5)、`MEMORY_L3_REBUILD_EVERY_N_CONSOLIDATIONS`(5)、
`MEMORY_TOOL_CHAT_ENABLED`(True)。封装为 `MemoryConfig` / `DEFAULT_MEMORY_CONFIG`。

---

## 7. 接口契约（供前端"记忆管理"页 — 协议我们定，UI 前端职责）
复用真实后端接口域风格（当前 control 域为 Mock 占位）：
| 操作 | 请求 | 响应 |
|---|---|---|
| 列出 | `memory:list` `{layer?: l1\|l2\|l3, page, pageSize}` | `{items:[{id,text,category,ts,confirmed}], total, page}` |
| 新增(手动) | `memory:add` `{text, category, layer?}` | `{id}` |
| 删除 | `memory:delete` `{id, layer}` | `{deleted:true}` |
| 清理 | `memory:clear` `{layer?}` | `{cleared:true}` |
| 重建 L3 | `memory:rebuild` | `{ok:true}` |

> 后端侧已实现抽取/存储/注入与工具；上述 HTTP/WS 接口为**待前端联调**的真实后端接口域
> （chat:send/history/personality/memory/voice:settings/auth:policy 均为 Mock 占位的一部分）。

## 9. 成功标准
- 跨 session：用户自报身份/偏好后，新对话球球能自然引用（走 L2/L3）。
- L1 只在会话结束触发抽取，不 per-run（一次 20 轮对话，抽取调用 1 次）。
- 分层可观察、可重建；注入受 clamp；回归通过；`personality.md` 未动。
