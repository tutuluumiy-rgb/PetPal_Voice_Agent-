# Research Topic Compiler

Take a fuzzy product question ("will users pay for X?", "is feature Y worth shipping?") and turn it into a research run plan an analyst or PM can execute in a week.

## When to use

- A PRD needs evidence that the team does not yet have.
- The user asks for "user research plan", "竞品分析", "可行性论证".
- After `brainstorming`, before or in parallel with `prd-architect`.

## Workflow

1. **Reframe** the question into a falsifiable research question (one sentence, with success/fail criteria).
2. **Choose the lightest method** that can answer it:
   - Existing data → analytics query
   - Competitor data → secondary research
   - Behavioral intent → usability prototype + 5 users
   - Purchase intent → pricing page / concierge / fake-door
   - Deep motivation → interviews (last resort)
3. **Draft the run plan**:
   - Hypothesis (1 sentence)
   - Method + sample size + recruitment
   - What you will measure / observe
   - **Decision criteria**: what answer means GO / PIVOT / KILL
   - Timeline + cost
4. **Surface product-decision coupling**: how this research answers a downstream product decision (e.g., commitment to build, sequencing, pricing).
5. **Hand off** to research owner with explicit decision date.

## Output

A Markdown research plan ≤ 2 pages, with clear go / pivot / kill thresholds so the team can act on the result without re-debating.
