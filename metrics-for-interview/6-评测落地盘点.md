# 评测落地盘点 — 现有代码能测什么，还缺什么

> **用途**：对照 `2-指标字典.md`，盘点 `backend/` 现有代码 / 已有测试脚本，找出哪些指标**已经能测**、哪些**缺闭环**。
> **结论先行**：核心测量管道已在 `main.py` 里跑着（timing / barge_in），**缺口集中在 4 处**：反向指标测试台、长会话压力、工具成功率批量统计、LLM 主观评测。

## 二、缺口的根因

1. **反向指标（M6.3 / M7.4）**：需要"播放中注入声音"的测试环境——不是测 VAD 判定（已有），而是**测 TTS 是否被正确停/不停**。这是运行时闭环测试，现有脚本没覆盖。
2. **长会话（M7.3）**：现有 probe 都是单轮/短序列，没有 30+ 轮级联压力测试。
3. **工具成功率（M4.1/M4.2）**：`test_agent.py` 是功能正确性测试（assert 具体输出），不是"批量任务 → 统计成功率"。
4. **拟人度/人设（M2.1/M5.1）**：需要 LLM 评测链路（rubric → LLM 打分 → 人工抽样），零代码基线。
