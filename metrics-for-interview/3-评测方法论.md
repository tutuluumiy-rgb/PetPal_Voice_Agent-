# 评测方法论 — 大模型 + 人工双轨评测

> **受众**：AI 产品岗面试官
> **作者**：PetPal 作者（自研展示项目）
> **目的**：展示"我是怎么测指标的"——这是 AI 产品 PM 最稀缺的能力之一
> **配套阅读**：`1-能力维度模型.md`、`2-指标字典.md`

## 一、为什么 AI 产品不能用纯埋点 + 看板

传统产品评测（DAU / 留存 / 转化率）依赖**真实用户在真实场景的批量行为**。AI 语音产品有 3 个失配：

1. **单次体验 ≠ 累计体验**——用户判断"它像不像人"，1 次对话就够了；要留存，得要 5 次
2. **质性指标占大头**——"拟人度 / 情感 / 对话质量"全是主观分，没法纯埋点
3. **Demo 阶段没有真实用户**——硬做埋点只会得到一堆空表

**结论**：必须用 **大模型模拟用户 + 人工复核** 的双轨评测体系。

## 二、双轨评测架构

```
┌──────────────────────────────────────────────────┐
│  评测输入：测试用例集（rubric + 脚本）             │
└───────────────┬──────────────────────────────────┘
                │
                ▼
┌──────────────────────────────────────────────────┐
│  轨道 A · 大模型评测（LLM-as-a-Judge）             │
│  · 覆盖量：80% 维度自动打分                        │
│  · 速度：分钟级                                    │
│  · 偏差：已知有 bias，需校准                        │
└───────────────┬──────────────────────────────────┘
                │
                ▼
┌──────────────────────────────────────────────────┐
│  轨道 B · 人工评测（rubric-driven）                │
│  · 覆盖量：20% 关键维度抽样                         │
│  · 速度：小时–天级                                  │
│  · 角色：校准 LLM + 兜底主观维度                     │
└───────────────┬──────────────────────────────────┘
                │
                ▼
┌──────────────────────────────────────────────────┐
│  输出：指标值 + 置信区间 + bias 声明                │
└──────────────────────────────────────────────────┘
```

## 三、轨道 A · LLM-as-a-Judge 设计

### 3.1 用什么 LLM 评

**原则**：用**强模型评弱模型**，避免"自己评自己"的偏差放大。

- **评估者**：Claude / GPT-4 / DeepSeek-V3 等强基座
- **被评估者**：PetPal 当前用的 DeepSeek
- **绝不**用同一模型（即使是不同版本）做评估——会被 prompt 偏好带偏

### 3.2 评测维度 → LLM 评测可行性

| 维度 | LLM 可评？ | 为什么 |
|---|---|---|
| D2 拟人度主观评分 | ✅ 可 | 用 MOS prompt + rubric |
| D5 对话质量（人设一致性） | ✅ 可 | 文本可直接给 LLM 看 |
| D4 工具调用成功率 | ✅ 可 | 工具调用日志结构化 |
| D6 首字延迟 | ❌ 不可 | 这是端到端运行时数据，必须真测 |
| D7 鲁棒性 | 🟡 部分 | 异常路径可生成，真实压测不行 |
| D1 / D3 留存意愿 | ❌ 不可 | 需要真人真实反馈 |

**结论**：**对话质量类维度（D2 / D4 / D5）→ LLM 自动评**；**系统能力类维度（D6 / D7）→ 必须真测**；**用户体感类维度（D1 / D3）→ 必须人工**。

### 3.3 LLM 评测 Prompt 模板（举例 D2 拟人度）

```
你是一个资深的语音产品评测员。请根据以下对话，对 AI 宠物的"拟人度"打分（1–5）。

【评分维度】
- 5 分：用户无法分辨是 AI
- 4 分：高度拟人，但偶有机械感
- 3 分：像 AI 但有"人味"
- 2 分：明显是 AI 但能对话
- 1 分：完全机械

【对话记录】
{conversation}

【输出格式】
{
  "score": <1–5>,
  "evidence": ["具体引用对话轮次 1", "具体引用对话轮次 2"],
  "issues": ["第3轮语气词使用不当", "第5轮回答重复"]
}
```

**为什么强制要 evidence 和 issues**——避免 LLM 给"3 分"但不告诉你为什么。

### 3.4 LLM 评测的偏差控制

**已知偏差**（学术界已确认）：

| 偏差 | 表现 | 缓解 |
|---|---|---|
| 位置偏差 | 偏好先出现的回答 | 随机化顺序，每个用例评 2 次取均 |
| 长度偏差 | 偏好更长的回答 | rubric 显式声明"简洁是优点" |
| 自我偏好 | 偏好自己风格的输出 | **必须用不同模型家族评估** |
| 格式偏差 | 偏好格式更整齐的输出 | 把结构化输出标准化再评 |

**缓解措施**：
- 每个用例**至少评 2 次**（顺序反转）
- 取**中位数而非均值**（抗异常）
- **每月做一次人工抽样校准**（轨道 B 兜底）

## 四、轨道 B · 人工评测设计

### 4.1 谁来评 / 评什么

**评测人员**：内部 3–5 人（不需要 AI 专家，但需要"普通用户"视角）

**评测维度**（只评 LLM 评不了的）：

| 维度 | 评测方式 | 样本量 |
|---|---|---|
| D1 主动对话意愿 | 模拟使用 30 分钟，事后访谈"愿不愿继续聊" | 3–5 人 × 1 次 |
| D3 留存意愿 | 用 3 天，次日是否主动打开 | 3–5 人 × 3 天 |
| D2 / D5 的"惊喜感" | 评分+自由描述（哪一刻觉得最像人 / 哪一刻最出戏）| 3–5 人 × 5 个关键时刻 |

### 4.2 人工评测 rubric（举例 D2 拟人度的"惊喜感"）

| 等级 | 描述 | 触发条件举例 |
|---|---|---|
| 5 | "我忘了它在测试" | 主动开口聊到 30 分钟不停 |
| 4 | "像跟一个真朋友聊" | 主动说出"它比我预期的像人" |
| 3 | "像在用 AI 但不反感" | 全程能完成对话 |
| 2 | "时不时出戏" | 至少 2 次"啊这是 AI"的反应 |
| 1 | "不如跟 siri 聊" | 提前终止测试 |

**关键设计**：rubric 里**有具体行为**（"主动说出…""至少 2 次"），不是抽象等级，避免评测员各自理解。

## 五、双轨怎么衔接

```
每个指标都有一行「评测方式」字段：

M2.1 拟人度主观评分 (MOS, 1–5) → LLM 评 + 人工 20% 抽样校准
M4.1 工具调用成功率 → LLM 评（解析日志）
M6.1 首字延迟 → 自动化测试（不在双轨里）
M1.2 主动开口响应率 → 仅人工（模拟用户用）
```

**衔接原则**：
- LLM 评的指标，**至少 20% 要被人工复核**——不验证，面试官会问"你怎么知道 LLM 评得对"
- 人工评的指标，**至少 50% 要有 LLM 预评分**——避免评测员个人偏好主导

## 六、面试讲法（3 分钟版本）

> **Q**：你怎么测你的 AI 产品的指标？
>
> **A**：我用了 **大模型 + 人工双轨评测**：
>
> 1. **大模型评测**——用 Claude 评 DeepSeek，能覆盖文本类维度（拟人度 / 对话质量 / 工具调用成功率），速度分钟级
> 2. **人工评测**——3–5 人内测，覆盖**真人才能感受的**维度（主动对话意愿 / 留存 / 惊喜感）
> 3. **双轨衔接**——LLM 评的指标 20% 人工复核，人工评的指标 50% LLM 预评分，避免偏差
> 4. **偏差声明**——我知道 LLM-as-a-Judge 有位置 / 长度 / 自我偏好偏差，所以我**用不同模型家族评估**、每个用例评两次取中位数
>
> 这样我的指标**既能批量跑（量），又能校准（质）**，适合 Demo 阶段样本少的特点。

**反问预警**：面试官可能问"LLM 评 LLM 真的准吗"——这是经典质疑。**回答要点**：
- 引用学术界 LLM-as-a-Judge 与人类一致率的研究（GPT-4 vs 人类 80%+ 一致率）
- 强调**你的缓解措施**（不同家族 / 多次评分 / 抽样校准）
- 强调**你的置信区间**（不是给一个数字，而是给一个区间）

## 七、这个方法论的诚实声明

- **LLM-as-a-Judge 不替代真人**——它是**低成本高覆盖**的工具，不是真理
- **人工评测样本小**——Demo 阶段不可避免，**讲清楚就好**
- **指标可能随功能变化漂移**——TTS 拟人化做完后，D2 拟人度评分标准要重新校准
- **评测不是一次性**——**每月一次**是基线，每次重大改动后**立即做一次**

## 八、为什么不直接用现成评测平台

像 Chatbot Arena、SuperCLUE 这类平台：

| 维度 | 现成平台 | 我的双轨 |
|---|---|---|
| 公开对比 | ✅ 强 | ❌ 弱（自评） |
| 自定义维度 | ❌ 弱 | ✅ 强（按我的 7 维度） |
| 时延类指标 | ❌ 不测 | ✅ 强（端到端运行时） |
| 拟人度专测 | 🟡 一般 | ✅ 强（定制 rubric） |

**取舍**：我**用通用平台做横向 benchmark**（"我和 GPT-4 比拟人度差几个点"），但**用自建双轨做产品迭代**（"这次改进了拟人度多少"）。

## 九、与能力维度模型的对应关系

| 评测方式 | 适用维度 |
|---|---|
| 仅 LLM 自动评 | D4 任务完成、D5 对话质量 |
| LLM + 人工抽样 | D2 情感体验 |
| 仅人工 | D1 主动对话意愿、D3 留存意愿 |
| 仅自动化测试（不在双轨）| D6 实时响应、D7 鲁棒性 |

**这意味着**：5 个能力维度走双轨评测，2 个维度走自动化测试。**任何指标都明确知道自己的评测方式**——这是 PM 应有的严谨。
