# 能力维度模型 — PetPal Voice Agent 评估框架（v2 定稿）

> **受众**：AI 产品岗面试官
> **作者**：PetPal 作者（自研展示项目）
> **目的**：展示"我如何系统化地评估一个 AI 语音 Agent 产品"
> **配套阅读**：`2-指标字典.md`（每指标怎么测）、`3-评测方法论.md`（大模型 + 人工双轨）

---

## 一、为什么不用通用指标框架（NSM / AARRR / HEART）

通用框架是给成熟 SaaS 用的，对 AI 语音 Agent 有三个失配：

1. **不看"拟人度"**——NSM / AARRR 全在量业务结果，没人告诉你"像不像人"
2. **不看"对话能力"**——HEART 看体验但不深入到对话质量
3. **不看"系统能力"**——语音 Agent 是端到端管道，**单点延迟就是产品体验**

我用一个**能力维度模型**替代：把"一个好的 AI 语音宠物"拆成 5 个**可独立评估的能力维度**，每个维度 1–3 个指标。

## 二、v1 → v2 变更说明（诚实展示取舍）

| 变更 | v1 | v2 | 原因 |
|---|---|---|---|
| L1 用户体感层 | D1 主动对话意愿 / D2 情感体验 / D3 留存意愿 | **只保留 D2** | D1/D3 依赖真实用户行为数据，**Demo 阶段测不了**；不立测不了的指标 |
| D2 情感体验 | 3 项（拟人度 / 情绪一致性 / 好感度）| **1 项：拟人度主观评分** | 其他两项当前无法可靠测量 |
| D4 任务完成率 | 3 项 | **2 项：工具调用成功率 / 多步任务完成率** | work 模式是核心场景 |
| D5 对话质量 | 3 项 | **1 项：人设一致性** | 其他两项与 D2 重叠 |
| D6 实时响应 | 3 项 | **2 项：E2E 延迟 / barge-in 响应延迟** + 反向误停率 | 思考占位命中率测了意义不大 |
| D7 鲁棒性 | 3 项 | **3 项：误打断率 / 端到端成功率 / 长会话稳定性** + 反向漏打断率 | 完整保留 |

> **删掉不测的，不是没测完，而是不想假装**。这是 Index 体系的核心哲学——**指标数量少是特点，不是缺陷**。

## 三、最终框架：5 维度 × 8 正指标 + 2 反向指标

```
┌────────────────────────────────────────────────────┐
│  对话能力层（"它聊得好不好"）                        │
│    D2 情感体验      —— 拟人度主观评分                 │
│    D4 任务完成率    —— 工具调用成功率 / 多步任务完成率 │
│    D5 对话质量      —— 人设一致性                     │
├────────────────────────────────────────────────────┤
│  系统能力层（"管道扛得住吗"）                        │
│    D6 实时响应能力  —— E2E 延迟 / barge-in 响应延迟   │
│                       ↳ 反向：误停率                │
│    D7 鲁棒性        —— 误打断率 / 端到端成功率 /     │
│                        长会话稳定性                  │
│                       ↳ 反向：漏打断率               │
└────────────────────────────────────────────────────┘
```

## 四、维度详解

### D2 · 情感体验（对话能力层）

**为什么 PM 必须看**：AI 语音宠物与聊天 UI 的差异点就在"像不像活物"。

| 指标 | 定义 |
|---|---|
| **拟人度主观评分**（MOS，1–5 分）| 用户/模型对"像不像人"的主观打分 |

**意图**：用一个可评测的指标描述"拟人化"这种抽象能力。

---

### D4 · 任务完成率（对话能力层）

**为什么 PM 必须看**：work 模式是宠物"能干"的证明，也是车载语音控车（同构能力）的背书。

| 指标 | 定义 |
|---|---|
| **工具调用成功率** | 成功返回工具结果 / 总工具调用次数 |
| **多步任务完成率** | 需要 ≥2 次工具调用的链路任务中，完整跑通的比例 |

**意图**：单步能力 + 链路能力的双层验证。

---

### D5 · 对话质量（对话能力层）

**为什么 PM 必须看**：人设一致性决定"它是年年还是随便一个 AI"。

| 指标 | 定义 |
|---|---|
| **人设一致性** | 宠物回答是否符合设定人格（撒娇/傲娇/委屈/犯困），出戏率 |

---

### D6 · 实时响应能力（系统能力层）

**为什么 PM 必须看**：**语音产品的延迟就是产品本身**——首字 1 秒和 3 秒是两个产品。

| 指标 | 定义 |
|---|---|
| **E2E 延迟** | 用户说完话 → 宠物开始发声（p50 / p95）|
| **barge-in 响应延迟** | 用户插话 → 宠物停声（p50 / p95）|
| **反向：误停率** | 用户没插话（或只是环境音）→ 但 TTS 被停了 的比例 |

**反向意图**："快"的代价是"乱停"。正确指标 = 延迟低 **且** 不乱停。

---

### D7 · 鲁棒性（系统能力层）

**为什么 PM 必须看**：Demo 现场最怕翻车，鲁棒性=“不翻车”。

| 指标 | 定义 |
|---|---|
| **误打断率** | 用户没插话，但系统确认打断了 的比例 |
| **端到端成功率** | 一轮完整对话（说→听→想→答→播）成功的比例 |
| **长会话稳定性** | 30+ 轮会话不崩溃、不卡死、能完成的概率 |
| **反向：漏打断率** | 用户真插话，但系统没识别、继续播放 的比例 |

**反向意图**：D6 反向（误停）与 D7 反向（漏断）是一对——**一个管"别乱停"，一个管"该停必停"**，是 barge-in 状态机的两面，面试讲这个对偶是亮点。

## 五、为什么是 5 个维度（删掉该删的而不是堆砌）

- **保留 D2 情感体验** —— AI 语音宠物的灵魂
- **保留 D4 / D5** —— work + chat 双模式正好对应"能干 + 会聊"
- **保留 D6 / D7** —— 语音管道的命脉，体现"我懂延迟与误判"
- **删除 D1 / D3** —— 需要真实用户数据，Demo 阶段测不了，**不假装有数字**
- **不加 D8 安全 / D9 成本** —— 不是不重视，而是当前用户场景（Demo）优先级低；如果未来 To C 化，首先补这两维

**触发条件**：若产品进入真实用户场景，**先回补 D1（主动对话意愿）和 D3（留存意愿）**——这是唯一正确的扩展方向。

---

## 六、面试 5 分钟讲法

如果面试官只给 5 分钟，**只讲这 3 个**（按重要性）：

1. **D2 拟人度主观评分** —— "我如何定义并评测拟人这种抽象概念"
2. **D6 实时响应能力** —— "首字延迟 + barge-in 延迟，外加误停率做反向约束"
3. **D7 鲁棒性** —— "误打断 / 漏打断是对偶，是我双层打断架构的直接映射"

**再补一句**："Demo 阶段我砍掉了需要真实用户数据的维度（留存、推荐、主动意愿），因为测不了就不假装有数。"
