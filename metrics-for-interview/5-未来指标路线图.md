## 二、每阶段的指标影响

### P1 · 句间停顿 + 思考占位声 + 语气词（拟人化改造 P1）

| 指标 | 影响 | 怎么测 |
|---|---|---|
| M2.1 拟人度 | **直接提升**（核心收益）| 改造前后各评一次，对比得分 |
| M5.1 人设一致性 | 风险项（停顿做过头 = 啰嗦）| 出戏率 + 停顿时长分布 |
| M6.1 E2E 延迟 | **有 trade-off**（插 sleep 增加延迟）| 延迟 p95 必须盯住，不能因拟人化牺牲响应 |

**面试亮点**：你主动指出"拟人化会牺牲延迟"这个 trade-off，评测体系里 **D6 反转指标（误停率）+ M6.1 延迟** 正好能体现你懂权衡。

### P2 · 主动开口调度器（拟人化改造 P2）

| 新增指标 | 定义 | 怎么测 |
|---|---|---|
| M1.2 主动开口响应率 | 宠物主动说话 → 用户回应比例 | 只有人工评测能测（需真实用户或模拟用户）|

**这里的诚实点**：M1.2 依赖用户行为，Demo 阶段**仍测不了** → 保持"不立测不了的指标"原则，进入真实用户阶段才补齐。

### P3 · TTS 拟人化（情感 TTS + 情绪连续）

| 指标 | 影响 | 怎么测 |
|---|---|---|
| M2.1 拟人度 | **最大驱动因子**（TTS 是听感大头）| 改造前后对比 |
| 新增：情绪连续性 | 相邻多轮 TTS 情绪标签是否连贯（不 5 秒内"开心→委屈→开心"）| LLM 评测 + 人工抽样 |

**要补的评测系统**：主动提到"情绪连续性"是 M2.1 的**反面专业化**——拟人度是整体感觉，情绪连续性是它的核心可测分解。

## 三、路线图的排序逻辑

1. **P1 停顿时最先**：成本最低（几行代码），对 M2.1 拟人度收益最大（拟人化改造分析 已排序）
2. **P2 主动开口**：架构级新增，但**评测价值有限**（Demo 阶段测不了）→ 排后
3. **P3 TTS 拟人化**：最影响听感 → 但依赖更强 TTS 能力 → 排最后

**这个排序本身就是 PM 决策**——不是"哪个炫做哪个"，而是"哪个对核心指标贡献大且成本低先做"。

## 四、未来要补的评测能力

| 时序 | 补什么 | 为什么 |
|---|---|---|
| 现在 | 自动化测试台（插话/噪声注入）| D6/D7 全部依赖 |
| P1 后 | 拟人度对比评测（A/B）| 验证改进是否有效 |
| P2 后 | 模拟用户脚本 | 主动开口触发验证 |
| P3 后 | 情绪连续性 rubric | 拟人度可测分解 |
| 真实用户阶段 | D1 主动对话意愿 + D3 留存 | 唯一扩展方向 |

## 五、面试讲法

> "我的路线图是按**指标收益 × 成本**排的：先做成本最低、对拟人度贡献最大的停顿（P1），TTS 拟人化是对听感影响最大的（P3），但依赖能力升级所以排最后。而且我**主动弃用了 Demo 阶段测不了的指标**（留存/主动意愿），等真实用户阶段再补——评测体系不是一次建完的，是跟着产品走的。"
